\textbf{ABSTRACT}
\vspace{0.5cm}
\hrule
\vspace{0.5cm}
%\cleardoublepage

Python's Global Interpreter Lock forces CPU-bound workloads into multiprocessing architectures, yet the language's native IPC mechanisms---pipes, queues, and raw shared memory---impose serialization overhead, kernel-mediated copies, or manual synchronization that limit throughput for the megabyte-scale payloads common in computer vision and scientific computing. This thesis presents \texttt{rs\_ipc}, a Rust-based shared memory library that provides zero-copy inter-process communication for Python through PyO3 bindings on Linux.

The library's \texttt{SharedMessage} abstraction combines a cache-aligned memory layout with bit-packed atomic fields and futex-based synchronization operating via direct system calls. Readers detect and access new data without acquiring any mutex (lock-free version checking), while a configurable \texttt{ReaderWaitPolicy} transforms the same channel from a lossy real-time data bus (immediate overwrite) to a reliable ordered message queue (full consumer acknowledgment)---selected at construction time without code changes. All blocking operations release Python's GIL, enabling true multithreaded concurrency during IPC waits.

A comprehensive evaluation compares \texttt{rs\_ipc} against five alternative backends---\texttt{multiprocessing.Queue}, \texttt{Pipe}, \texttt{shared\_memory}, ZeroMQ, and POSIX IPC---across four benchmark scenarios spanning three communication topologies, replicated on three hardware configurations. In single-producer single-consumer scenarios, copy mode achieves 0.19\,ms median latency (8.9$\times$ faster than \texttt{multiprocessing.Queue}). In 1:10 fan-out, the lock-free reader path yields a scalability ratio of 2.3$\times$ compared to 20$\times$ degradation for semaphore-based signaling, sustaining 2.5\,GiB/s aggregate throughput. An overhead decomposition reveals that 95\% of end-to-end latency in pickle-based workloads originates in Python's serialization layer---establishing a quantitative ceiling that bounds the benefit of further transport optimization. The evaluation also identifies a critical trade-off: under 10:1 writer contention, zero-copy mode exhibits catastrophic tail latency (90$\times$ determinism ratio) due to extended lock holding during serialization, while copy mode maintains bounded behavior (1.8$\times$). These findings yield deployment guidelines mapping communication topology and payload characteristics to optimal operating mode.
