\textbf{ABSTRACT}
\vspace{0.5cm}
\hrule
\vspace{0.5cm}
%\cleardoublepage

Python's native inter-process communication mechanisms exhibit significant performance limitations in data-intensive applications requiring low-latency transfer of large payloads. This thesis presents \texttt{rs\_ipc}, a high-performance IPC library implemented in Rust that provides zero-copy shared memory communication for Python through PyO3 bindings.

The library introduces a \texttt{SharedMessage} abstraction with cache-aligned memory layout, bit-packed atomic fields, and futex-based synchronization primitives operating directly via Linux system calls. The design enables lock-free read-side version checking, flexible producer-consumer policies (non-blocking, partial-blocking, full-blocking), and GIL-free operations that permit true Python multithreading during IPC.

A comprehensive evaluation compares \texttt{rs\_ipc} against six alternative backends---\texttt{multiprocessing.Queue}, \texttt{Pipe}, \texttt{shared\_memory}, ZeroMQ, and POSIX IPC---across four communication topologies. In single-producer single-consumer scenarios, the copy mode achieves 0.19\,ms median latency (9.4$\times$ faster than \texttt{multi\-processing.Queue}). In fan-out topologies (1:10), the lock-free reader path yields a scalability ratio of 2.4$\times$ compared to 19$\times$ degradation for semaphore-based alternatives, sustaining 2.5\,GiB/s aggregate throughput. For pre-serialized payloads, raw shared memory throughput exceeds 18\,GiB/s at message sizes of 1--8\,MiB. The evaluation also identifies a critical trade-off: under writer contention (10:1), the zero-copy mode exhibits catastrophic tail latency due to extended lock holding during serialization, while the copy mode maintains predictable performance. These findings yield concrete deployment guidelines mapping communication topology to optimal operating mode.
